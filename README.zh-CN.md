# 剪辑室 Cutting Room

[English](README.md) | **中文**

这是一个给编码 agent 用的剪辑 skill。它做三件事。把素材盘清楚，在达芬奇里把时间线剪出来，交活之前按一套固定的标准把自己评一遍。

## 安装

在终端里跑这条命令。

```bash
curl -fsSL https://raw.githubusercontent.com/Maoxintao98/cutting-room/main/install.sh | bash
```

脚本会克隆仓库、检查 SKILL.md、给脚本加上执行权限，并提示缺哪个依赖。它默认装到 `~/.agents/skills/cutting-room`，对你在任何项目里都生效。

也可以自己克隆。

```bash
# 装给自己，所有项目都能用
git clone https://github.com/Maoxintao98/cutting-room ~/.agents/skills/cutting-room

# 只装给某个仓库
git clone https://github.com/Maoxintao98/cutting-room <你的仓库>/.agents/skills/cutting-room
```

调用时写 `$cutting-room`，也可以直接说要干什么，比如"审一下这条片子"。

## 四种用法

| 用法 | 你的处境 | 它给你什么 |
|---|---|---|
| 定方案 | 素材在手，不知道从哪下手 | 先把片种和目标问清楚，再给这个片种的技法侧重 |
| 剪辑 | 方案有了，时间线还没有 | 在达芬奇里建时间线、铺片段、加字幕、调声音 |
| 审片 | 片子剪完了，自己看花了眼，找人评又怕对方客气 | 六维评分、时间码证据，还有能用／需修／重做的结论 |
| 选片 | AIGC 生成了几十条，挑到麻木 | 瑕疵三级分类，加上 KEEP／可修／NG 的决策树 |

第一件事要问清楚剪的是什么片子。品牌氛围片和叙事短片要的技法经常是相反的，不问就上手，多半白干。

## 八条底线

审片难在两处，一是不敢说，二是乱说。下面八条防的就是这两件事。

**一、不奉承，不软化。** 禁用语是「整体不错，但是……」「瑕不掩瑜」「提点小建议」。不因为片子是谁做的就改口径。该重做就说重做。得罪人算这份工作的成本，不是失误。

**二、不凑数。** 不为了显得专业而编造问题，没问题就说没问题。反过来也一样，不为了格式对称硬找优点。强行平衡本身就是不诚实。

**三、每条判断都要有证据。** 指得出时间码或者镜头号的才写。震撼、高级、有质感、节奏不错这类词不加分，它们只是噪音。

**四、分清事实、共识和偏好。** 个人偏好必须标明是偏好，不能当结论用。把偏好当成标准，是审片最常见的失职。

**五、优点和缺点用同一把尺。** 优点要和缺点一样具体，还要指出全片最好的那一个镜头，说明它好在哪。片子好就明确说好，不要用"但是"给它打折。

**六、评价作品，不评价人。** 不评人不等于放水，对作品的判断该多严厉就多严厉。

**七、说"不行"要给出为什么和怎么改。** 只否定不给路，等于没评。

**八、不确定就说不确定。** 缺 Brief、缺平台、缺硬性要求，直接讲。别编。

## 报告长什么样

下面是虚构的一条片子，全片 25 秒。

```
片名/版本：demo-v1     片种：品牌氛围片     时长：25s     画幅：16:9
【信息缺口】未提供投放平台，可能影响对竖屏安全区的判断
────────────────────────────────────────────────
一、先说成立的
  1. 全片最好的镜头：第 12 秒，水滴落下时镜头向前推，运动方向与前一镜
     的旋转同向，是全片唯一一处真正接上的动势匹配剪
  2. 第 6 秒的 0.8 秒留白有动机，由动作触发，把注意力压回画面
  3. 色温全片统一

二、六维评分
  1 叙事推进            1/3   第 3 秒 与前后无因果关系
  2 视听协同与声音设计  2/3   第 18 秒 音乐全程同一电平，高潮前无推进
  3 视觉构成与图文      1/3   第 9 秒 字幕压在人物面部
  4 镜头间连续性        2/3   第 7 秒 全景硬切特写，无过渡支点
  5 信息与品牌一致性    1/3   看完无法确定在卖什么
  6 时间节奏与速度      2/3   第 15 秒 变速方向与下一镜动势相反

三、问题清单（按性价比排序）
  1.【高收益·低成本】第 18 秒 音乐缺推进 → 末段抬 4dB
  2.【高收益·低成本】第 3 秒 删掉该镜头 → 全片信息更清晰
  3.【高收益·高成本】第 5-9 秒 主体一致性有问题 → 需重新生成

四、结论
  ☐ 能用    ☑ 需修（改：音乐推进、第 3 秒删镜、第 5-9 秒重生成）
  一句话总评：单看每个镜头都成立，合起来不像同一支片子。
```

第三块里，问题清单按**改动成本和收益的比值**排序，不按严重程度排。一个十秒钟能改好的大问题，价值远高于一个要重拍的小问题。

## 底本

由 24 本书、19 篇论文、27 篇文章蒸馏而成，抽取全文约一千二百万字符。

书这一路从蒙太奇走到写实主义。论文是 2023 到 2026 年评估生成视频的研究。skill 把这些整理成一套统一方法，正文不带引用。

## 文件结构

```
SKILL.md                        主干与路由
agents/openai.yaml              UI 元数据
references/
  craft.md                      定方案：术语、优先级、剪接点、节奏、声音、蒙太奇、转场、机位
  resolve.md                    剪辑：达芬奇的工具契约，以及九条实战坑位
  review.md                     审片：客观性纪律、三遍看法、六维评分卡、报告模板
  clip-qc.md                    选片：瑕疵三级分类、选片记录表
scripts/
  probe.py                      用 ffprobe 盘点素材目录
  resolve_mcp.py                直连达芬奇的 MCP
  run_step.py                   在达芬奇里执行步骤脚本
  steps/00_inspect_timeline.py  交接前体检时间线
```

触发时只加载 `SKILL.md`，其余按需读。

## 实践验证

这条流水线在真实素材上完整跑过，一路从盘点 52 个片段的目录，到建工程、导入、建时间线，再读回来核对。

`references/resolve.md` 里那九条坑都是实操撞出来的，包括时间线从第 86400 帧起算这种不跑一次不会知道的事。
